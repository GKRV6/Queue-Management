# Queue Without Standing

A smart queue management system for college canteens, photocopy shops, clinics
and other campus service centers — a **database-focused academic project**.

Customers join a queue from their phone, get a digital token, watch their live
position and estimated waiting time, and are alerted when it is their turn.
Staff call the next token, serve, skip or re-queue customers from a counter
console. Administrators configure centers, counters, services and booking
slots, and study peak hours, waiting times, staff performance and feedback.

Everything runs on real database operations against a normalised relational
schema with 13 tables, 16 triggers, 7 views and 16 report queries — no mock data
in the UI.

## Quick start

Requirements: **Node.js 22.16 or newer** (uses the built-in `node:sqlite`; no
database server to install).

```bash
npm install
npm start            # creates data/qws.db with 3 weeks of sample data on first run
```

Open <http://localhost:3000> and use a one-click demo login:

| Role | Email | Password |
|------|-------|----------|
| Customer | `student@qws.edu` | `Student@123` |
| Staff (Main Canteen, Counter 1) | `staff@qws.edu` | `Staff@123` |
| Administrator | `admin@qws.edu` | `Admin@123` |

Other useful commands:

```bash
npm run db:reset              # rebuild the database with fresh sample data
npm run db:reset -- --days 7  # ...with only 7 days of history
npm run dev                   # auto-restart on file changes
npm test                      # 49 unit, integration and HTTP tests
npm run test:coverage         # with coverage report
```

Environment variables: `PORT` (default 3000), `DB_FILE` (default
`data/qws.db`), `SESSION_SECRET` (random per start if unset — set it to keep
logins across restarts), `NODE_ENV=production` (adds the `Secure` cookie flag
and skips the demo accounts/sample data unless `SEED_DEMO=1`).

## Features

**Customer**
- Browse service centers with live waiting count, open counters, shortest wait and rating
- Join a queue now or **book a time slot** (capacity-limited); add a note for staff
- Live token tickets: position, people ahead, estimated wait, "go to Counter 2 now" alert
- Cancel a token, view its full status timeline
- History of visits with real waited/served minutes; **star rating + comment** for served tokens
- Notifications: token issued, turn near (top 3), called, skipped, completed, cancelled

**Staff**
- Counter console: open / pause / close the counter
- **Call next** (priority first, then first-come-first-served across all services the counter handles; booked tokens wait for their slot)
- Start serving → complete (with remarks), skip absent customers, re-queue or mark no-show
- Prioritise a waiting token (emergency, accessibility)
- Pause / close / re-open the queues of their center; personal stats for the day

**Administrator**
- Overview KPIs and live status of every center
- **Peak-hour analytics**: weekday × hour heatmap, tokens and wait per hour, daily volume, rating distribution, per-service and per-staff tables — filterable by center and period
- Queue management by date; feedback browser
- Configure centers, services (token codes, service times, fees), counters (which services each handles), booking slots
- Create staff accounts (user + staff profile in one transaction) and reassign counters; activate/deactivate users
- **SQL Reports**: 16 documented queries from `db/queries.sql`, shown with highlighted SQL and run live
- **Schema Explorer**: tables, columns, keys, row counts, views, triggers and indexes read from `sqlite_master`

## Database design

See **[docs/DATABASE.md](docs/DATABASE.md)** for the ER diagram, normalisation
argument, constraints, triggers, views, transactions and report catalogue.

Highlights:
- 12 entities — User, ServiceCenter, Counter, ServiceType, Queue, QueueToken,
  ServiceStaff, ServiceRecord, TimeSlot, QueueStatusHistory, Feedback,
  Notification — plus the associative `counter_services` (Counter M:N ServiceType)
- BCNF; derived values (token codes, positions, waiting times) live in views, never in columns
- Token life-cycle **state machine enforced by a trigger**; every change is
  written to an append-only audit table and turned into a notification by triggers
- Business rules as **partial unique indexes** (one live token per customer per queue,
  one active token per counter)
- Multi-step operations in `BEGIN IMMEDIATE` transactions (join, call next, close queue, …)
- Sample data generated by **simulating** 3 weeks of arrivals through counters
  (lunch rush, clinic mornings, weekend dips), replayed through the real
  triggers so history, notifications, waits and ratings are internally consistent

## Design

The interface follows macOS / iOS conventions in a monochrome palette: a plain
white page in light mode or near-black in dark mode, black/white accents,
translucent glass for the floating sidebar and toolbar, a macOS-style sidebar
window, large rounded corners, pill buttons and segmented controls, tokens shown
as Wallet-style passes, and a floating glass tab bar on phones. Colour is only
used for meaning (green / orange / red status, yellow rating stars). Icons are
SF-Symbols-style line drawings (`public/js/icons.js`). The theme follows the
system setting until you pick light or dark with the sun/moon button (remembered
per browser).

## Architecture

```
public/                 Single-page app (vanilla ES modules, no build step)
  js/app.js             router, layout, notification polling
  js/views/*.js         customer, staff, admin screens
  js/ui.js, charts.js   escaping html`` templates, sheets, HTML charts
  js/icons.js           SF-Symbols-style SVG icon set
  css/app.css           liquid-glass design system (light + dark)
src/
  server.js             starts the app, creates + seeds the DB on first run
  app.js                Express app, security headers, JSON-only mutations
  db.js                 connection, schema loader, transaction helper
  auth.js               scrypt passwords, HMAC-signed session cookie, role guard
  routes/               auth, customer, staff, admin REST endpoints
  services/             queue transactions, staff console, analytics, admin
  seed/                 reference data + traffic simulation
db/                     schema.sql, triggers.sql, views.sql, queries.sql
test/                   node:test suites (schema, services, HTTP, seed, units)
```

API responses use one envelope: `{ "success": true, "data": …, "error": null }`.

| Area | Endpoints |
|------|-----------|
| Auth | `POST /api/auth/register · login · logout`, `GET /api/auth/me` |
| Customer | `GET /api/centers`, `GET /api/centers/:id`, `POST /api/tokens`, `GET /api/tokens/active · history`, `GET /api/tokens/:id/timeline`, `POST /api/tokens/:id/cancel · feedback`, `GET /api/notifications`, `POST /api/notifications/read-all · :id/read` |
| Staff | `GET /api/staff/dashboard`, `PATCH /api/staff/counter`, `POST /api/staff/call-next`, `POST /api/staff/tokens/:id/start · complete · skip · no-show · requeue · prioritize`, `PATCH /api/staff/queues/:id` |
| Admin | `GET /api/admin/overview · analytics · queues · feedback · staff · users · reports · reports/:name · schema`, CRUD on `centers`, `service-types`, `counters`, `time-slots`, `staff`, `users` |

## Security notes

- Passwords hashed with scrypt + per-user salt; sessions are HMAC-signed, `HttpOnly`, `SameSite=Lax` cookies
- Role checks on every route; staff actions are restricted to their own center/counter, customers to their own tokens
- All SQL uses bound parameters; the only dynamic SQL (admin updates) interpolates whitelisted column names
- State-changing requests must be `application/json` (blocks cross-site form posts); login is rate-limited
- Content-Security-Policy without inline scripts; all UI text is HTML-escaped by the `html` template helper

## Notes for evaluators

- Opening hours are shown but not enforced for joining, so the demo works at any time of day.
  Outside opening hours the seed adds a few live tokens per center so every dashboard has something to show.
- `node:sqlite` prints an "experimental" warning on Node 22; the npm scripts silence it.
